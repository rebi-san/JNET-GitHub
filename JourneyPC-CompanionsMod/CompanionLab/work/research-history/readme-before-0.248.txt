**Isolation requirement:** Journet is an independently distributed mod, not a separate Steam product. Public means listed in Journet's browser. The pinned original executable searches exact decimal `level` values. Mod rooms carry a nonnumeric `level` marker, start Steam-private until metadata publication, then use Steam Invisible for search without friends-list exposure. The mod validates metadata both before joining and after entry; native lobby operations and legacy P2P traffic are held in the injected process. Modern P2P has a separate virtual port and validates the actual remote Steam identity, lobby membership, room, nonce and compatible handshake before transport admission. Native gameplay admission is disabled in this test. Original game files and unmodified players are untouched. Offline contracts and fixtures are not live proof: verify with consenting mod and unmodified control clients before wider distribution. See [native audit](RESEARCH.md#steam-matchmaking-isolation-0162).

### Intended final-product startup process

1. Run Steam in **Online Mode**, signed into the player's own account, before launching Journey. Planned Steam lobby discovery, invitations and P2P connectivity require Steam online; Offline Mode is no longer the startup procedure.
2. Open `JNET.exe` and launch Journey through it.
3. Use the in-game Journet menu to create or join a lobby.

The Steam candidate isolates native matchmaking without disabling Steam itself. The 0.162 connection test requires everyone already in Desert; group travel remains outstanding. Launching Journey without JNET preserves the ordinary experience.

### Agreed interface and behavior

- Next online milestone: use Journey's own Steam application/account context for explicit public browsing, generated four-character code rooms and accepted Steam invitations. No custom backend, random pairing, automatic room creation or host migration. Three total players remain the supported limit; eight is a future gameplay target. The existing local transport is retained until the Steam adapter is verified.
- The online browser heading will be **Public**, with no Access column. Code rooms are excluded from that browser through Steam search filters; they are code-only in Journet, not secret from underlying Steam APIs. Code lookup must reject ambiguity rather than choose an arbitrary room. The 0.162 candidate replaces password entry with code lookup.
- Group travel is a new protocol around MEPAL-derived level behavior: show "[player name] wants to go to [level name]. Will you join them? Yes/No". No leaves the lobby and keeps the current level. Yes waits for a host-authorized transition after companion cleanup, then loads the selected level and rejoins synchronization. Missing responses must never imply consent. The host's disappearance cancels the transition/session; no automatic host migration is planned.
- JNET appears on the main title screen and whenever a launcher-prepared game is paused. Keep Journey's top-left controls; put the persistent lobby browser in the center, selected-room details and appearance on the right, and contextual actions along the bottom. Use the native menu lettering and open space with the game visible behind it.
- Browser columns: host, mode, current level and occupancy. A separate lobby name and connection-strength indicator are not required for the first implementation. The browser remains visible while joined and marks the current room.
- Public rooms are listed. Private rooms are code-only in the planned Steam integration and also support accepted invitations. The generated code replaces the host-chosen password. Discovery filters must exclude code-only rooms from the public browser; the menu filter alone is not sufficient.
- Confirm joining. If changing rooms, finish departure from the old room before connecting to the new one. Load the destination level from its normal start only when needed; joining the same level in the same mode must not reload or teleport the player.
- Appearance uses **Apply**, without leaving the lobby. Choices cover robe color/tier, scarf length, and Longtail only from ObjectOutfits. Keep the last applied choice until the native adapter acknowledges success. Longtail and scarf limits must come from validated native capabilities.
- Host-selected travel offers participants travel or leave. Normal game progression remains available. Include playable credits/prototype levels, excluding Level_Jacky. Level artwork will be supplied later.
- Changing between Journey and Rocket Death Match requires a coordinated level restart; mode support remains unavailable until the native mode adapter is implemented and validated.
- Distance alone must not remove JNET lobby membership. Audit native distance departure separately from connection timeout and chapter teardown.

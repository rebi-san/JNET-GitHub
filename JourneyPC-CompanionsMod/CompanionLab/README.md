This addresses the unprepared animation pointer read recorded at Journey RVA 0x001BAFC0. Native preparation is fingerprint-checked; invalid bindings decline character activation. Regression fixtures cover missing and mismatched bindings; live crash reproduction remains unverified.

0.273 refreshes native companion storage identities after level initialization independently of extra-traveler allocation, preserves the distinction between native New Journey travel and Chapter Select, tolerates lighting updates before particle effects are loaded, and keeps session reports refreshing past three minutes. Copy All and Save Session Report take a fresh status sample. Native admission safety checks remain enabled; Internet visibility and cutscene behavior require live validation.

0.272 preserves chirp numbering through travel and reconnects, applies host Day lighting explicitly (including same-level joins), and lets valid chirps use a still-fresh prior capture when a new capture fails. Portability and online audit: this is an x64 Windows package for the fingerprint-checked Steam Journey executable. The launcher handles Unicode paths, but the native private-asset bridge still uses ANSI paths shorter than MAX_PATH; arbitrary Unicode and long installation paths are not supported by that bridge. Lobby discovery requests worldwide Steam results, capped at 50, and Steam NetworkingSockets chooses P2P routes. Discovery is request-driven; metadata/membership caches and unchanged-state suppression limit redundant work. Host-forwarded guest traffic adds a hop. These checks do not establish compatibility with every Windows configuration, connectivity in every region, or globally optimal latency; real cross-region measurements are still needed.

0.264 copies menu text and shadow quads into a 16-byte-aligned temporary before native submission. This addresses the two 0.263 Character/World menu crashes at Journey RVA `0x1024cf`, where the native SIMD instruction received a misaligned quad pointer. The native quad remains 100 bytes; array alignment alone cannot align every element. The regression fixture checks all four input alignments against the original append instructions. Live menu recovery remains unverified.
See [setup and testing instructions](diagnostic/QUICKSTART.txt). The package contains only a short `README.txt` with the release version as its text documentation; the detailed guide stays in the source workspace.

JNET.exe loads the matching JNET.dll into a supported Steam Journey installation. The package includes private character assets, a short README and a hash manifest; it excludes Journey executables, personal configuration and runtime logs.

Windows installation is relative to `JNET.exe`: put `JNET/` inside any supported Steam Journey folder. Bottle-specific paths and test identities are not packaged configuration. Meet Everywhere is always enabled.

Session diagnostics use bounded in-memory buffers. Copy All includes diagnostic tails; Save Session Report writes the displayed report and retained client/runtime/fault/exit/forced-close records to a chosen file. No automatic diagnostic logs are created. Keep JNET open until a report is copied or saved; unsaved diagnostics are discarded when it closes. Necessary game/settings persistence is unchanged.

0.261 reserves four BlendNinja mesh instances in the private persistent startup candidate (original declaration: two), matching the existing remote rendering capacity. The 0.260 fault record identifies return RVA 0x261804 and the BlendNinjaAnimSet lookup. Native Mesh::BindInstance growth at 0x260AE0 expands exhausted instance storage and calls 0x261740 to initialize the new slots; that function dereferences the resource context at +0x50 through 0x264FF0. The recorded context is null and the failing read is at 0x28. Reserving the extra traveler slots during resource initialization avoids late growth after this context is unavailable. The patch changes only the pinned instanceLimit digit in the in-memory resource candidate; original executable/assets remain unchanged. 0.260 is a diagnostic follow-up, not a claimed startup fix. The user's 0.259 report reaches native level setup and extra-traveler initialization, then faults at Journey RVA 0x265044 reading address 0x28: the lookup object's RCX/RBP is null. This differs from the prior allocator breakpoint. Disassembly places the return address at RSP+0x58, outside the prior 64-byte stack sample, and multiple callers use the lookup. Fault records now retain their original first 82 fields, followed by extension version 1, an eight-bit read-success mask, and 512 bytes from fault-time RSP in eight bounded 64-byte reads. Failed blocks are zeroed. Records remain memory-only and exceptions remain unhandled. No animation, traveler, allocator, or logo-skip behavior is changed in this release; the extended report is needed to identify the caller before a functional correction.

0.259 addresses the allocator failure captured in the 0.258 report: Journey RVA 0xF0967 is the explicit breakpoint when a Lua allocation bucket is exhausted. The native realloc caller is 0xF0B24; the immutable pool table at RVA 0x5C38F0 provides only 16 blocks of 8192 bytes. JNET previously compiled the entire setup wrapper after every resource script. Setup is now split into three smaller cached functions, prepared once per Lua state through a short dispatcher; repeat calls still update settings and wrap newly loaded native definitions. A Lua 5.3 allocator fixture with collection paused measured 100 allocations in that bucket for 100 old-style setup calls versus zero for the cached setup. This isolates avoidable compilation pressure, not the complete live engine heap. Native allocator limits and exception behavior are unchanged. The prior 0.258 animation resource change did not resolve the user's startup crash; 0.259 still requires live startup confirmation.

## Retained troubleshooting material

`work/native/` contains disassembly and native maps; `work/pc_scripts/` contains extracted PC scripts. Keep these, toolchain dependencies, editor assets and test sources. `work/research-history/` preserves historical release notes and selected raw failure logs in structured form. Historical notes are evidence, not current setup instructions.

`work/install-*.json` records bottle installations. Keep the latest rollback for each recorded bottle, including original filenames and hashes; rollback snapshots must not be renamed internally. `work/cleanup-0.248.json` records the removed paths and retained evidence. Original game files and reference projects are outside this cleanup.

After each successful, hash-verified installation, delete the preceding build's release ZIP, version-specific Python installer script, and routine build log, plus any older superseded copies. Keep the current release ZIP, installer and log, the reusable `install-jnet.py` entry point, current installation receipts, and the latest rollback for each bottle.

Preserve important research and useful experiments, including their source, results, native maps, disassembly, fixtures, and any artifacts needed to reproduce or explain findings. Preserve logs that contain unique troubleshooting evidence in `work/research-history/` before deleting their old copies. Age alone does not make an experiment disposable. Do not remove active source tools or fixture scripts as installer cleanup; remove compiled experiment outputs only when they are reproducible and contain no unique evidence.
